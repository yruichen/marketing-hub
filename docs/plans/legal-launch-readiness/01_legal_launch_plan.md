# 01 上线前法律责任 Plan

版本：V1  
日期：2026-06-27  
适用阶段：封闭测试、公开 beta、正式商业化

> 本计划用于明确上线前必须处理的法律责任和执行阶段。所有法律文本、跨境数据、AI 生成内容标识和收费条款必须由律师最终复核。

## 2026-06-27 实施状态

已落地到代码：

- 条款版本和同意记录：新增 `PolicyDocument`、`UserConsent`，注册必须主动勾选服务条款和隐私政策，登录态返回当前条款同意状态，关键生成/工作流/资产/社区操作会校验当前条款同意。
- 法律文本版本占位：迁移初始化 beta 版服务条款、隐私政策、AI 使用规则、社区规则、素材授权、计费规则、BYOK 说明的 active policy record；正式文本仍需法务替换和复核。
- AI 生成内容标识和追溯：生成结果和资产 metadata 写入 `ai_generated`、生成任务、provider/model、prompt key/version、harness version、生成时间、用户/组织/项目、输入摘要；前端生成结果区显示“AI 生成初稿，发布前需人工审核”。
- 上传授权：手动创建资产必须确认拥有权利或授权，metadata 记录 `license_status`、`rights_confirmed_at`、`rights_confirmed_by`。
- 社区责任和举报：公开发布必须确认发布责任；新增内容举报、reported count、审核/隐藏/下架状态和 ops 处理接口；举报和处理进入 AuditLog。
- 私有数据隔离：社区/RAG 默认排除 hidden/removed 内容；RAG 默认不检索 private 内容，服务层 fallback 仅检索 public 和同组织 organization 可见内容。
- 生产风险检查：`DEBUG=False` 部署检查会拒绝危险配置，并要求 active 的服务条款和隐私政策存在。
- 验证：后端完整测试 85 个通过；前端 lint、build、Vitest 28 个测试通过。

仍未完成或需人工决策：

- 法务必须提供/复核正式服务条款、隐私政策、社区规则、素材授权、BYOK、计费/退款/发票文本；当前仅是 beta 版本记录和链接占位。
- 运营主体、注册地址、客服邮箱、投诉邮箱、数据保护联系人、第三方供应商清单仍需业务确认。
- 跨境数据、支付/税务、企业 DPA、正式商业化退款政策需要律师和财务确认。
- 举报处理目前具备 API 和审计闭环，完整运营后台队列、申诉表单和处理导出仍应在公开社区/模板市场开放前补齐。
- 高风险行业规则库和强制人工复核仍需规则运营和 review 工作流继续深化；当前仅完成 AI 标识、责任提示和审计基础。

## Phase 0：法律适用范围和责任主体确认

目标：先确认平台在哪些司法辖区、面向哪些用户、提供哪些 AI 服务，否则无法判断适用法律。

任务：

- 明确上线市场：仅中国大陆、港澳台、全球用户、还是邀请制内测。
- 明确服务对象：个人用户、企业团队、营销机构、品牌方、学生/未成年人。
- 明确服务类型：AI 文案、图片、视频、音频、工作流、社区分享、模板市场、BYOK、计费订阅。
- 明确运营主体：公司名称、注册地址、联系方式、客服邮箱、投诉邮箱、数据保护联系人。
- 明确第三方供应商：模型 provider、对象存储、邮件、支付、日志、错误追踪、分析工具。

交付物：

- 法律适用范围说明。
- 第三方处理者清单。
- 上线地区和功能开关表。

验收标准：

- 每个上线功能都有责任主体和适用法律初判。
- 没有责任主体或投诉渠道的功能不得公开上线。

## Phase 1：基础法律文本

目标：上线前必须具备用户可见、可记录版本、可追溯同意的法律文本。

任务：

- 起草并发布：
  - 服务条款 Terms of Service。
  - 隐私政策 Privacy Policy。
  - Cookie/SDK/第三方服务说明。
  - AI 生成内容使用规则。
  - 社区发布规则。
  - 模板/素材上传授权条款。
  - 订阅、额度、退款和发票规则。
  - BYOK 数据处理和密钥安全说明。
- 在注册、登录、首次生成、首次发布社区、首次上传素材、首次 BYOK 配置时展示关键提示。
- 记录用户同意：
  - user_id
  - policy type
  - policy version
  - timestamp
  - IP/user agent
  - consent source

交付物：

- 法律文本初版。
- 条款版本记录方案。
- 前端同意展示点位。

验收标准：

- 用户注册前可查看服务条款和隐私政策。
- 用户同意可被审计。
- 重大条款更新能触发重新同意。

## Phase 2：个人信息与数据安全

目标：满足个人信息处理、数据安全、访问控制、审计和删除要求。

任务：

- 做数据地图：
  - 账户信息。
  - 组织/成员信息。
  - 项目/品牌上下文。
  - 生成输入和输出。
  - 用户上传素材。
  - AI provider 调用日志。
  - 支付和额度记录。
  - 安全审计日志。
- 明确每类数据的处理目的、保存期限、访问角色、第三方共享情况。
- 增加数据主体权利流程：
  - 访问。
  - 更正。
  - 删除。
  - 导出。
  - 撤回同意。
  - 注销账号。
- 建立数据保留策略和删除策略。
- 完成敏感数据保护：
  - API key 加密。
  - 日志脱敏。
  - 上传 URL 校验。
  - RBAC。
  - 审计日志。

交付物：

- 数据地图。
- 数据保留策略。
- 数据主体请求处理 SOP。
- 安全事件响应 SOP。

验收标准：

- 数据字段能映射到隐私政策。
- 用户可请求删除账号和数据。
- 管理后台访问敏感数据有审计。
- 生产环境关闭 demo/mock/匿名访问风险配置。

## Phase 3：AI 生成内容责任和标识

目标：让 AI 输出可识别、可追踪、可解释、可申诉。

任务：

- 所有 AI 输出存储生成元数据：
  - task_type
  - provider
  - model
  - prompt_key
  - prompt_version
  - harness_version
  - generated_at
  - user_id
  - organization_id
  - project_id
  - source inputs digest
- 前端对 AI 输出显示“AI 生成初稿，发布前需人工审核”。
- 图片、音频、视频、文案资产保存 `ai_generated=true`。
- 社区发布和外部导出保留 AI 生成标识。
- 高风险内容进入 review 流程。
- 建立 AI 输出投诉和纠错入口。

交付物：

- AI 生成内容标识规则。
- 生成元数据 schema。
- 高风险内容审核策略。
- AI 输出投诉处理 SOP。

验收标准：

- 任一公开内容能追溯到生成任务和责任用户。
- 用户不能误以为 AI 输出是平台担保的最终广告内容。
- 社区内容可被举报、下架、复核。

## Phase 4：广告、知识产权和社区内容

目标：降低营销内容天然存在的广告合规、素材授权、版权和商标风险。

任务：

- 广告合规：
  - 禁止绝对化用语。
  - 禁止未经证实的销量、功效、认证、排名。
  - 高风险行业默认提示人工审核。
  - review 节点输出具体风险和替代表达。
- 知识产权：
  - 上传素材时要求用户确认拥有授权。
  - 模板/社区发布要求用户授予平台展示、复制、分发必要许可。
  - 提供侵权投诉入口和下架流程。
  - 禁止用户上传第三方商标、肖像、字体、音乐等未授权素材用于公开模板。
- 社区内容：
  - 建立举报、下架、申诉、复核流程。
  - 管理后台可冻结用户、隐藏内容、记录处理原因。
  - 社区搜索和 RAG 不得默认检索私有资产。

交付物：

- 广告合规规则库初版。
- 上传授权声明。
- 社区规则。
- 侵权投诉和下架 SOP。

验收标准：

- 公开发布前用户必须确认其对内容承担发布责任。
- 社区内容有可执行的处理流程。
- 私有项目内容不会进入公共社区或公共 RAG。

## Phase 5：商业化、运营和事故响应

目标：收费、企业 BYOK、运营后台和安全事故处理具备法律可解释性。

任务：

- 计费：
  - 明确订阅计划、额度消耗、超额策略、退款规则、发票说明。
  - 记录用户购买、额度扣减、余额变化和账单。
- BYOK：
  - 说明用户自行配置第三方模型 key 的责任。
  - 明确平台如何加密存储和使用 key。
  - 明确第三方 provider 对数据处理的责任边界。
- 事故响应：
  - 数据泄露、违法内容、模型输出高风险、滥用攻击、密钥泄露分别有处理流程。
  - 明确通知用户、监管、第三方 provider 的触发条件。
- 运营后台：
  - 管理员操作必须审计。
  - 冻结、删除、下架、额度调整必须记录原因。

交付物：

- 订阅和退款规则。
- BYOK 条款。
- 事故响应 runbook。
- 管理后台审计要求。

验收标准：

- 未完成收费条款和账单记录前不得收费。
- 未完成 BYOK 密钥安全和条款前不得开放企业 BYOK。
- 未完成事故响应 runbook 前不得开放公开 beta。

# 01 用户体验升级计划

## 0. 目标

目标不是把界面做得更热闹，而是让测试用户能明确理解：

1. 我现在在哪个组织、项目、活动下工作。
2. 我下一步应该做什么。
3. AI 正在做什么、是否卡住、失败后怎么恢复。
4. 生成结果如何进入资产库、审阅、复用和导出。
5. 哪些操作会消耗额度，消耗多少。

当前前端已经具备完整 App Shell 和模块入口，但用户主路径仍偏“功能集合”。上线测试前要把它收束成“营销生产流程”。

## 1. 目标用户视角诊断

### 1.1 极度挑剔用户会质疑什么

- 我登录后为什么先进“灵感风暴”，而不是清楚知道自己的项目和品牌是否已配置？
- 首次引导填了品牌信息，但是否真的保存到了项目品牌记忆？
- 内容包、文案、图片、分镜、配音、视频之间是什么关系？
- 工作流和一键内容包是不是重复功能？
- 生成失败时是我输入错、额度不足、模型问题，还是系统问题？
- 资产库里的东西能不能搜索、筛选、再次生成、导出、分享、审阅？
- 计费页说的成本和我刚刚生成的任务是否一一对应？
- 社区/模板库里的内容是公开的，还是只在我的组织内？
- AI 设置里面的“平台密钥”和“自有 API Key”会不会泄露？

### 1.2 运营专家会关注什么

- 测试用户是否能在首日完成 Aha Moment。
- 是否有足够的行为数据判断用户卡在哪。
- 失败体验是否会让用户放弃。
- 产品是否在引导用户沉淀资产和复用模板，而不是一次性生成后离开。
- 是否能区分个人创作者、小团队、代理商和企业用户的核心需求。
- 是否有运营后台追踪测试邀请、激活、任务成功率、成本异常和反馈。

## 2. 信息架构升级

### 2.1 当前结构

`frontend/src/app/navigation.ts` 已有：

- 开始：灵感风暴、首页
- AI 内容生成：一键内容包、写文案、做配图、写分镜、配旁白、做视频
- 项目与管理：我的项目、工作流、资产库、审阅
- 系统：模板库、个人主页、计费、AI 设置

这个结构覆盖面足够，但对新用户而言入口过多，容易不知道该先做哪个。

### 2.2 测试期推荐结构

保留当前导航，但调整默认心智：

| 层级 | 用户语言 | 当前对应模块 | 升级动作 |
| --- | --- | --- | --- |
| 第一步 | 创建品牌项目 | 我的项目、首次引导 | 强制将 onboarding 写入 Project.brand_context |
| 第二步 | 生成第一份内容包 | 一键内容包、灵感风暴 | 统一为“从 brief 到内容包”主 CTA |
| 第三步 | 细化单项内容 | 文案/图片/分镜/配音/视频 | 单项生成显示“来自当前项目品牌记忆” |
| 第四步 | 自动化复用 | 工作流 | 将工作流解释为“保存团队 SOP” |
| 第五步 | 管理产物 | 资产库、审阅 | 每个结果自动入资产并可送审 |
| 第六步 | 成本和设置 | 计费、AI 设置 | 只给 admin 暴露 key 和高级成本 |

### 2.3 首页升级

当前 `DashboardPage` 和 `AnalyticsDashboardView` 已有任务、成本、趋势、provider、健康度数据。上线测试前首页应改成“行动仪表盘”。

需要新增的首页区块：

- 今日待处理：失败任务、待审阅内容、未完成工作流。
- 快捷继续：上次编辑的项目、上次运行的工作流、最近资产。
- 新手进度：品牌记忆是否完整、是否生成首个内容包、是否保存首个资产、是否邀请成员。
- 成本提醒：本月额度余额、近 7 天消耗趋势、异常高成本任务。
- 系统状态：AI provider 是否配置、是否使用 mock fallback、队列是否积压。

验收标准：

- 用户登录后 5 秒内能看到“下一步做什么”。
- 没有项目时显示创建项目 CTA，而不是空图表。
- 有失败任务时首页必须显示失败原因和重试入口。
- 首页不展示 `celery_task_id`、raw payload 等调试信息。

## 3. Onboarding 升级

### 3.1 当前问题

`frontend/src/features/onboarding/OnboardingModal.tsx` 是 5 步引导，但 `completeOnboarding()` 主要写 `localStorage` 和本地 `contentPackage` state，并跳到 `content`。它不保证后端 Project.brand_context 被创建或更新。

### 3.2 升级方案

Onboarding 必须成为真实数据写入流程：

1. 如果用户没有项目，创建 Project 和默认 Campaign。
2. 如果已有项目，提示“更新当前项目品牌记忆”或“创建新项目”。
3. 将 brandName、industry、audience、tone、forbiddenWords、referenceLinks、channels 写入 `Project.brand_context`。
4. 自动生成第一份内容包任务，写入 `GenerationTask`。
5. 生成完成后创建 Asset，并将用户带到内容包结果页。

### 3.3 字段升级

当前字段：

- 使用场景
- 品牌名称
- 行业
- 目标人群
- 语调
- 禁用词
- 参考链接
- 渠道
- 模板
- brief

建议补充：

- 产品/服务名称
- 主要卖点，最多 5 条
- 转化目标：种草、留资、购买、私域、品牌认知
- 内容限制：夸大宣传、医疗金融敏感词、竞品禁提
- 示例素材：支持上传或粘贴链接

验收标准：

- 关闭页面再打开，onboarding 写入的品牌信息仍在项目页可见。
- 生成结果的 prompt payload 中包含当前品牌记忆摘要。
- 后台能统计 onboarding 完成率和每步放弃率。

## 4. 生成体验升级

### 4.1 当前问题

`useGenerationTask.ts` 同时支持同步任务和轮询，但多数生成体验仍由各 Panel 自己拼 payload、setLoading、setAgentLogs。长任务和短任务的 UI 模式不统一。

### 4.2 统一任务模型

所有生成入口都改成：

1. 提交任务。
2. 立即返回 task id。
3. UI 进入任务卡片。
4. 轮询或 SSE/WebSocket 更新状态。
5. 成功后展示结果并入资产。
6. 失败后展示可解释错误和恢复动作。

任务卡片应显示：

- 任务类型：文案、图片、分镜、音频、视频、工作流节点。
- 当前状态：排队中、运行中、保存资产中、完成、失败、已取消。
- 预计耗时：根据历史 task_type P50/P95。
- 消耗预估：普通用户显示“将消耗少量额度”，admin 显示 token/cost。
- 失败恢复：重试、换模型、复制输入、联系管理员。

### 4.3 错误文案升级

需要从技术错误变成用户可行动信息：

| 技术错误 | 用户文案 | 动作 |
| --- | --- | --- |
| 401/403 | 登录状态已过期或无权限访问当前项目 | 重新登录/切换项目 |
| 402 | 当前额度不足，无法继续生成 | 查看计费/联系管理员 |
| 429 | 请求太频繁，系统正在保护你的额度 | 稍后重试/查看队列 |
| provider timeout | 模型响应超时，输入可能过长或服务拥堵 | 缩短输入/换模型/重试 |
| fallback mock | 当前返回演示结果，未调用真实模型 | 前往 AI 设置配置模型 |
| validation error | 输入缺少必要信息 | 高亮缺失字段 |

验收标准：

- 任意生成失败都不能只显示 `Task submit failed`。
- 视频长任务刷新页面后能从任务中心继续查看。
- 同一任务不会因为用户连续点击提交而重复扣费，必须依赖 idempotency key。

## 5. 项目与品牌记忆

### 5.1 当前问题

项目模块已经比较完整：`ProjectManager` 支持搜索、视图切换、文件夹、项目详情、品牌记忆编辑。但品牌记忆仍是自由 JSON，缺少完整度、版本、引用证据和生成影响说明。

### 5.2 升级动作

- 品牌记忆从自由表单升级为分区：
  - 基础：品牌名、行业、产品、官网。
  - 受众：目标人群、痛点、购买动机。
  - 风格：语调、视觉风格、标题偏好、emoji/标点偏好。
  - 禁区：禁用词、合规红线、竞品限制。
  - 渠道：小红书、抖音、公众号、视频号、邮件。
  - 参考：爆款案例、历史资产、参考链接。
- 增加品牌记忆完整度：0-100。
- 生成入口显示“本次将使用哪些品牌记忆”。
- 每次品牌记忆修改写入 AuditLog。
- 支持品牌记忆版本：当前版本、历史版本、恢复版本。

验收标准：

- 新用户能理解“为什么要填品牌记忆”。
- 修改品牌记忆后，下一次生成 payload 可追踪到版本号。
- Viewer 只能查看品牌记忆，Creator/Admin 才能编辑。

## 6. 工作流体验

### 6.1 当前问题

工作流已有 React Flow、节点、边、属性面板、运行、重试、只读分享、保存草稿。但对非技术用户来说，节点 I/O schema、DAG、上下游输出等概念仍偏工程。

### 6.2 升级动作

- 将节点命名改成业务动作：
  - Context -> 读取品牌记忆
  - RAG Search -> 查找历史素材
  - Copy -> 写渠道文案
  - Image Prompt -> 生成图片提示词
  - Image Generation -> 生成配图
  - Review -> 内容审阅
- 工作流模板增加“适用场景”和“预计产物”。
- 运行前检查：
  - 是否有品牌记忆。
  - 是否有断开的必要节点。
  - 是否存在循环。
  - 预计消耗和预计耗时。
- 运行中显示节点级进度，不只显示整体完成。
- 运行后将每个节点输出自动变成资产或草稿。
- 节点失败支持“只重试失败节点”和“从此节点重新向后运行”。

验收标准：

- 一个无技术背景的运营能知道每个节点的业务意义。
- 工作流运行失败后不需要重跑全链路。
- 工作流模板可从成功项目一键保存。

## 7. 资产库体验

### 7.1 当前问题

资产库已支持列表、筛选、新建、编辑、删除、预览和分页。但 Asset 模型目前仅有 `source_url`、`tags`、`metadata`，生产级媒体生命周期不足。

### 7.2 升级动作

- 资产详情页：
  - 预览内容。
  - 来源任务。
  - 所属项目/活动。
  - 生成模型和成本。
  - 使用记录。
  - 审阅状态。
  - 下载/复制/再次生成/送审。
- 资产类型扩展：
  - copy/document、image、audio、video、brief、template。
- 搜索升级：
  - 标题、标签、内容、项目、活动、任务类型。
  - 后续接入向量检索。
- 批量操作：
  - 批量打标签。
  - 批量移动项目。
  - 批量导出。
  - 批量删除进入回收站而不是硬删。

验收标准：

- 每次成功生成都能在资产库找到。
- 资产预览不依赖第三方临时链接永久可用。
- 删除资产有确认和审计日志。

## 8. 审阅体验

### 8.1 当前问题

`ReviewPage` 当前更像本地内容包版本切换，缺少真正的后端审阅对象、评论、审批状态和多人协作。

### 8.2 升级动作

新增 ReviewItem 模型或基于 Asset 增加审阅状态：

- 状态：draft、in_review、changes_requested、approved、rejected。
- 评论：字段级或段落级 comment。
- 指派：assignee、reviewer。
- 版本：AI 初稿、用户修改稿、最终稿。
- 审阅任务列表：按项目、成员、状态过滤。

验收标准：

- Creator 可提交审阅。
- Ops/Admin 可批准或打回。
- Viewer 可评论但不能批准。
- 审阅通过的资产可标记为“可发布”。

## 9. 模板库/社区体验

### 9.1 当前问题

`CommunityCreationView` 和 `RAGSearchView` 默认 `CommunityCreation.objects.all()`，对测试环境很危险：私有组织素材和公开社区素材边界不清。

### 9.2 升级动作

- 拆分“团队模板库”和“公开社区”。
- CommunityCreation 增加 visibility：private、workspace、public。
- public 发布必须二次确认，且脱敏项目/客户信息。
- 模板库默认只显示组织内模板。
- RAG 搜索默认只搜当前组织和已授权 public 内容。

验收标准：

- 用户明确知道发布到哪里。
- 私有项目素材不会出现在其他组织检索结果中。
- 公开模板有举报/下架机制。

## 10. 个人主页和运营增长

当前 Profile 已有公开作品墙和统计。上线测试期建议只作为“创作者资料和反馈入口”，不要过早变成社区社交产品。

升级动作：

- 个人主页显示测试反馈入口。
- 展示用户产出数量、被赞数、最近项目，但默认仅工作区可见。
- 支持导出个人作品集链接，但需明确可见范围。

验收标准：

- 用户可关闭公开展示。
- 管理员可下架违规公开作品。

## 11. 可访问性与移动端

必须完成：

- 所有 icon button 有 `aria-label` 或 tooltip。
- 弹窗可 Esc 关闭，焦点不丢失。
- 表单错误要绑定字段，不只 toast。
- 移动端导航不遮挡主内容。
- 长标题、长项目名、长错误消息不撑破布局。

验收标准：

- Keyboard only 可完成登录、创建项目、提交生成。
- 主要页面在 375px 宽度不出现不可操作按钮。
- 错误 toast 不遮挡关键 CTA。

## 12. 用户体验指标

封闭测试必须埋点或日志化：

- 注册完成率。
- 邮箱验证完成率。
- Onboarding 每步完成率。
- 首次项目创建率。
- 首次内容包生成率。
- 首次任务成功率。
- 首次资产查看率。
- 工作流保存率。
- 工作流运行成功率。
- 失败任务重试率。
- AI 设置完成率。
- 计费页访问率。
- 7 日留存。

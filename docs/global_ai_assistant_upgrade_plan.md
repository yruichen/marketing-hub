# 全局 AI 助手升级计划

版本：V1
日期：2026-06-25
范围：全局 AI 助手、上下文理解、可执行工具调用、任务模式、审计与评测

## 1. 背景

当前全局 AI 已经可以使用，但它更接近“可对话的辅助入口”。如果要做到行业领先，它需要从聊天面板升级为“懂当前业务现场、能执行跨模块任务、能解释判断依据、能持续学习偏好”的产品级助手。

核心差距不在模型回答能力本身，而在产品系统能力：

- 是否能理解用户当前所在页面、项目、活动、工作流节点和正在处理的素材。
- 是否能把建议直接转成可执行操作，而不是只给用户一段文字。
- 是否能在长任务中持续展示计划、进度、风险和下一步。
- 是否能沉淀组织、项目、品牌和用户偏好，形成可控记忆。
- 是否能被评测、审计和回放，保证关键操作可靠。

## 2. 目标体验

目标不是做一个更大的聊天框，而是做一个贯穿 Marketing Hub 的智能操作层。

用户应该可以这样使用全局 AI：

- “帮我检查这个工作流为什么跑不出结果。”
- “把这个项目下最近三条素材整理成小红书发布计划。”
- “根据当前活动目标，生成一个更稳的 workflow 并替换现有草稿。”
- “这个节点失败了，帮我定位原因并只重跑失败部分。”
- “帮我把这个品牌的语气记住，以后生成内容都按这个风格。”
- “对比当前方案和上周版本，告诉我风险和成本变化。”

完成后的助手应该具备：

- 上下文感知：知道用户当前在哪里、在看什么、能操作什么。
- 工具执行：能安全地创建、更新、运行、重试、归档、搜索和跳转。
- 任务编排：复杂请求能拆成步骤，并显示执行进度。
- 主动诊断：发现工作流、项目、计费、素材或配置异常时给出具体修复路径。
- 可审计：每次读写操作有日志、摘要、影响范围和回滚建议。
- 可评测：关键能力有固定用例，避免后续迭代让助手变得不可靠。

## 3. 核心能力模块

### 3.1 深度上下文

助手需要读取并组织多层上下文：

- 全局：当前组织、用户角色、订阅计划、可用模型、用量预算。
- 项目：当前项目、文件夹、收藏、最近素材、活动目标。
- 页面：当前 tab、当前面板、选中对象、过滤条件、搜索词。
- 工作流：当前 draft、节点、边、运行状态、失败原因、生成资产。
- 内容：最近生成的文案、图片、分镜、音频、发布渠道和风格偏好。

建议新增一个前端上下文聚合层：

- `assistantContext`：由 App、ProjectManager、WorkflowBuilder、BillingPage 等页面注册当前上下文。
- 只传必要摘要，不把完整大对象塞进每次对话。
- 对敏感或高成本上下文做显式开关，例如“附带当前工作流详情”。

### 3.2 工具调用层

全局 AI 要从“建议”变成“可执行”。第一阶段建议支持这些工具：

- 项目工具：创建项目、设为当前项目、移动到文件夹、收藏/取消收藏。
- 工作流工具：创建 draft、整理布局、运行工作流、重试失败节点、定位节点、打开属性面板。
- 素材工具：搜索资产、绑定资产到节点、生成内容包、导出结果。
- 计费工具：查看用量、解释超限原因、推荐升级或 BYOK 配置。
- 导航工具：跳转到项目、工作流、计费、社区、设置中的具体位置。

工具调用必须有安全边界：

- 读操作可以直接执行。
- 写操作需要明确预览：操作对象、影响范围、是否可撤销。
- 高风险操作需要二次确认，例如批量删除、覆盖现有 workflow、切换关键配置。
- 每个工具返回结构化结果，便于助手继续推理和 UI 展示。

### 3.3 任务模式

复杂请求应该进入任务模式，而不是一次性回答。

任务模式 UI 建议包含：

- 任务标题和目标。
- 步骤清单：待执行、执行中、已完成、失败、需要确认。
- 当前步骤的工具调用结果。
- 可中断操作：暂停、取消、继续、改目标。
- 最终交付：结果摘要、已变更对象、下一步建议。

典型任务：

- 检查并修复工作流运行失败。
- 基于项目目标生成完整 campaign workflow。
- 把散乱素材整理为发布计划。
- 分析计费用量异常并给出优化建议。

### 3.4 主动诊断

行业领先的助手不应该只等用户问。它应该能在关键页面识别明显问题，并用低打扰方式提示：

- 工作流存在孤立节点、循环风险、缺少输入、失败节点。
- 当前项目没有活动目标或品牌语气，导致生成结果不稳定。
- 计费用量接近上限，某个 provider 成本异常。
- 生成结果缺少发布渠道适配或审核步骤。
- 用户在同一页面多次失败操作，提示“是否需要我帮你检查”。

第一阶段不要做强打断式弹窗，建议使用：

- 右上角助手徽标的小提示。
- 面板内诊断卡片。
- 工作流运行面板中的“AI 检查”入口。

### 3.5 可控记忆

记忆必须可见、可编辑、可删除，不能变成黑盒。

建议分三类：

- 品牌记忆：语气、禁用词、竞品、视觉风格、渠道偏好。
- 项目记忆：目标人群、活动周期、核心卖点、历史结论。
- 用户记忆：常用工作方式、默认输出格式、偏好模型。

产品要求：

- 每条记忆标明来源和更新时间。
- 助手引用记忆时可展开查看。
- 用户可以一键禁用某条记忆对当前任务的影响。
- 重要记忆写入前需要确认。

### 3.6 审计与回放

全局 AI 一旦能执行操作，就必须有审计能力：

- 每次工具调用记录 actor、时间、输入摘要、输出摘要、影响对象。
- 重要写操作记录 before/after 摘要。
- 助手面板中展示“本次任务改了什么”。
- 后端保留可查询的 AI operation log。
- 出错时能把任务上下文打包成 debug 信息，方便定位。

### 3.7 评测体系

要避免助手升级后“看起来更聪明但实际更不稳定”，需要建立 eval：

- 上下文识别：能否正确识别当前项目、工作流和选中节点。
- 工具选择：能否选择正确工具，不乱改数据。
- 失败诊断：能否定位常见 workflow 失败原因。
- 安全确认：高风险操作是否要求确认。
- 结果质量：输出是否贴合品牌、渠道和任务目标。
- 回归测试：旧能力不因新增上下文和工具而退化。

## 4. 分阶段实施

### Phase 1：上下文与诊断入口

目标：让全局 AI 明确知道用户当前在哪，以及能对当前页面给出具体建议。

改动：

- 新增前端 assistant context store。
- App 顶层注册当前 tab、项目、活动、订阅和用户角色。
- WorkflowBuilder 注册当前 draft、节点数量、失败节点、运行状态。
- ProjectManager 注册当前选中项目、文件夹和收藏状态。
- BillingPage 注册当前计划、项目额度和用量摘要。
- AssistantPanel 首屏增加“当前上下文”摘要和“检查当前页面”入口。

验收：

- 用户在工作流页问“这里有什么问题”，助手能引用当前 draft 和节点状态。
- 用户在计费页问“为什么超限”，助手能读取当前计划和用量摘要。
- 用户在项目页问“帮我整理这个项目”，助手能识别当前选中项目。

### Phase 2：工具调用基础设施

目标：让助手能安全执行低风险操作。

改动：

- 定义 assistant tools schema。
- 实现导航、定位节点、整理布局、运行工作流、重试失败节点等工具。
- 前端展示工具调用卡片：待确认、执行中、成功、失败。
- 写操作先返回 preview，用户确认后执行。

验收：

- “帮我定位失败节点”可以自动打开对应节点和右侧面板。
- “帮我整理这个 workflow”可以触发整理布局，并保留撤销能力。
- “重跑失败节点”只重试失败节点，不重新运行全量流程。

### Phase 3：任务模式

目标：把复杂请求从单轮问答升级为可跟踪任务。

改动：

- AssistantPanel 增加 task mode。
- 后端或前端维护 task step 状态。
- 每个步骤可关联工具调用结果。
- 支持暂停、取消、继续。

验收：

- “帮我检查并修复这个工作流”会拆成检查、诊断、建议、确认、执行、复核。
- 用户可以在执行前看到 AI 将修改哪些对象。
- 任务完成后能看到结果摘要和下一步建议。

### Phase 4：可控记忆

目标：让品牌、项目和用户偏好长期生效，但保持透明可控。

改动：

- 新增 memory 数据结构和设置入口。
- 助手生成时可读取相关记忆摘要。
- 重要记忆写入需要用户确认。
- 面板中展示“本次使用的记忆”。

验收：

- 用户保存品牌语气后，后续文案生成能稳定遵循。
- 用户可以删除或禁用某条记忆。
- 助手不会在用户不知情的情况下写入重要记忆。

### Phase 5：审计与评测

目标：让全局 AI 的可靠性可衡量、可回放、可持续迭代。

改动：

- 新增 AI operation log。
- 为关键工具调用补充后端测试。
- 增加 assistant eval fixtures。
- 建立常见场景的回归测试清单。

验收：

- 每次 AI 写操作都能查到影响对象。
- 常见误操作可以通过日志定位。
- 关键场景升级后有稳定回归测试。

## 5. 优先级结论

第一优先级是 Phase 1 和 Phase 2：上下文 + 工具调用。没有上下文，助手无法真正懂当前业务现场；没有工具调用，助手只能停留在建议层。

第二优先级是 Phase 3：任务模式。它决定全局 AI 能否承接复杂工作，而不是只处理短问答。

第三优先级是 Phase 4 和 Phase 5：记忆、审计、评测。它们会让助手从“能用”走向“可长期信任”。

短期最值得做的三个落点：

- 在全局 AI 中显示当前页面和对象上下文。
- 给工作流接入 AI 诊断和工具执行：定位失败节点、整理布局、重试失败节点。
- 给助手加任务模式雏形：把复杂请求拆成可见步骤，并显示执行进度。
